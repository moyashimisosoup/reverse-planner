## 0. 方針とゴール

**キーワード：SOFT PIXEL（やさしい8bit）**。
「かわいいレトロゲームの触り心地」と「現代の計画ツールの直感的な操作」を両立させる。昔のゲーム画面そのものは再現しない。ドット絵、2～4pxの立体影、押すとへこむボタン、時間差のあるカードスライドインで小さな楽しさを生む。

守る原則：
1. **いつ終えたいか → やること → 結果 → 実行**の一本道。現在の「くらし/まなび」×「時刻/日付」2軸の同時提示をやめる。
2. **一画面一つの決定**。高度な設定は段階的に開く。最初の入力画面では締切と作業名・時間だけを見せる。
3. **主役は行動**。残り時間の確認や達成演出が、タスクへの着手を邪魔しない。
4. **レトロさは装飾と反応に限定**。本文の可読性・通常のフォーム操作・キーボード操作を犠牲にしない。
5. **ユーザーの意思を尊重**。勝手にタスクを削除・短縮・提出完了扱いにしない。最小行動分割は任意。
6. **共通逆算コアは維持**。学習固有の習熟度・復習計画は今回のUI改修で実装しない。
7. **実機検証可能な小刻みの実装**。デザインだけでなく使用可能な機能と保存データを維持する。

### v0.2の成功条件（仮説・合格基準）

- 初めて開く人が、説明を読まなくても「時刻まで／日付まで」の違いを理解し、**期限 → 作業追加 → 結果**へ到達できる。
- 重要操作に明確なタップ対象・言葉・結果がある。既存v0.1の逆算、作業編集、完了、タイマー、JSON出力、保存が失われない。
- 画面幅320px～デスクトップ、文字拡大200%、キーボード操作で主要な操作が可能。
- 初回演出後、操作ごとのアニメーションに待たされない。Reduced Motion時も同一の情報・機能が残る。
- GitHub Pagesで配信し、iPhone Safari・デスクトップブラウザで実機操作を検証してから公開版v0.2を完成扱いする。

## 1. 情報設計と導線

### 1.1 全体の流れ

~~~text
HOME
 ├─「何時までに終えたい？」 → SETUP(clock)
 ├─「何日までに終えたい？」 → SETUP(days)
 └─「続きから」※既存データがある場合 → PLANまたはRUN
SETUP（締切・やること・所要時間）
 ├─「くわしく設定」折りたたみ
 └─「予定をつくる」 → PLAN
PLAN（はじめる目安、余裕・不足、予定の内訳）
 ├─「計画を調整」 → SETUP（入力値は保持）
 ├─「この計画ではじめる」 → RUN（clock）
 └─「今日の作業を見る」 → RUN相当の今日カード（days）
RUN（今の作業、タイマー／完了、次の予定）
 ├─「一時停止」「できた」「見直す」
 └─「一覧に戻る」 → PLAN
~~~

ブラウザの戻る、各画面の戻るボタンは入力中の内容を消さずに動作する。画面スタックの扱いは小さなUI状態機械を推奨。URL hashを使う場合でもGitHub Pagesのリポジトリ配下パスを壊さない。

### 1.2 利用シーンの分類を後ろへ

- ホームで **くらし/まなび** を必須選択させない。
- SETUPの任意の「例から始める」で、**出発準備／家事／旅行／宿題／テスト勉強**を選べるようにする。テンプレートは編集可能なサンプルであり実課題だと誤認させない。
- テンプレート選択は、内部の共通Coreとは無関係。ユーザーは自由入力で同じ計画を作れる。
- 学習専用の「習得」「復習」等はv0.2では案内文・今後の予定に留め、利用可能だと誤解させない。
- 現在のv0.1は4つの独立シート（life/study × clock/days）を持つ。v0.2ではまずこのデータを保持しながら表向きの導線を統一し、複数計画の本格管理は別段階の機能にする。

### 1.3 初回と再訪の差

- 初回：保存データがなければ2択の入口を見せる。「デモを見る」は任意。サンプルを本人のタスクとして無断登録しない。
- 再訪：実データがある場合は「続きから」と「新しい計画」の2つを表示。最後に利用した計画へ戻る。
- サンプル由来のデータは常に「サンプル」と表示し、ユーザーが編集した時点で本人の計画として扱う案を検証する。v0.1の既存サンプルを移行時に実作業扱いにしないこと。

## 2. 画面ごとの仕様

### S0: HOME（入口）

必須表示：短いタイトル「いつまでに終わらせたい？」、大きな2枚の選択カード、実データがある場合のみ「続きから」。

- 左（または上）：「⏰ 何時まで？」：今日の出発・家事・短い学習に適した **datetime-local** へ。
- 右（または下）：「📅 何日まで？」：旅行準備や試験までの **date** へ。
- 視覚アイコンは最終的に一貫した自作/ライセンス確認済みSVGの16/24pxピクセルモチーフに置き換える。
- カード全体がクリック領域。通常のリンク/ボタン相当のセマンティクスでフォーカス可能。
- 下部に目立ち過ぎない「仕組み・プライバシー・GitHub」への導線。
- 「レベル」等のゲーム要素は得点・ランク表示にしない。飾りとしても誤認を避ける。

### S1: SETUP（作業と締切）

表示順：
1. ステップ名「ゴールを決めよう」＋締切日時（日付モードは締切日）
2. 作業カードの縦リスト：名称、推定分数、完了状態（既存データの場合）
3. 「＋ やることを追加」ボタン → 追加行。所要時間のチップは5/10/15/30/60分、数値も直接編集可能。
4. 折りたたみ「くわしく設定」：時刻は予備分、日付は1日の可能分数・休む曜日・予備日。
5. 画面下の主CTA「▶ 予定をつくる」。入力が妥当でない場合は操作可能な説明とともに修正箇所へ導く。

挙動：
- 重要なのは新規追加と修正の簡便さ。削除/順序変更は小さく配置し、誤タップ対策を行う。
- 名前・分数の編集確定タイミングを明確化し、入力途中でリスト全体を再描画してフォーカスを失わせない。
- タスクが0件、分数0/空欄、過去の日時、締切日超過時にはエラーをフィールド近傍に文章で表示。
- 長い入力リストをスマホで扱うため、CTAは必要に応じて下部に固定。ただしキーボード表示時に入力を隠さない。
- 手動並べ替えと↑↓操作を両立。ドラッグ操作だけに依存しない。

### S2: PLAN（結果・確認）

**上部の大きな1枚**：時刻モードなら「17:20から始めよう」、日付モードなら「今日は30分が目安」。締切との関係も明記。

- 予定が成立：大きな開始目安と開始CTA。
- 予定が成立しない：**不足○分 / 未割当○分**を表示。最初の選択肢は「計画を調整する」。締切延長が可能なら案として提示、実際の変更は承認後に反映。
- 時刻モード：開始/終了時刻とカード名・所要時間を一列のタイムラインに。
- 日付モード：今日・明日・以後のカードで、割当分数と作業を表示。予備日・休みの日は区別。
- 主CTA：時刻なら「この計画ではじめる」、日付なら「今日の分を見る」。補助：「やることを直す」。
- 「計画結果」と「計画確定」は区別。入力変更の際は計算結果だけを更新する。

### S3: RUN（実行）

時刻モード：現在の1作業名、残り時間、▶開始/一時停止/できた、次の作業カード、一覧へ戻る。

- 完了は明示操作でのみ記録。タイマーが0秒になっても自動完了しない。
- 作業が中断・延長されたら残りの見通しを再計算してPLANから比較できるようにする。
- 時間超過時に失敗演出や煽りを行わない。時計は安定表示。
- 日付モード：その日の作業カードと完了チェック。分単位タイマーは選択的な機能として後続で追加可能。
- 確認画面への戻り先と保存対象は明示して混乱を避ける。

### 画面別の主CTA一覧

| 画面 | 主CTA | 副CTA | 変化 |
| --- | --- | --- | --- |
| HOME | 何時まで？ / 何日まで？ | 続きから | SETUPへ |
| SETUP | 予定をつくる | 詳しく設定 / 戻る | 計算してPLANへ |
| PLAN | この計画ではじめる / 今日の分を見る | 調整する | RUNへ |
| RUN | できた！ | 一時停止 / 一覧に戻る | 完了記録・次へ |

## 4. ビジュアルルール（デザイントークン案）

### 4.1 配色案

| トークン | 色 | 用途 |
| --- | --- | --- |
| --paper | #F6F2E8 | アプリの背景 |
| --surface | #FFFDF7 | カード・入力面 |
| --ink | #36463E | 基本文字・枠線 |
| --mint | #BFE5D4 | 進行・選択 |
| --peach | #F5B5A8 | 完了・励まし |
| --honey | #F6D68A | 注意・予備 |
| --muted | #63746A（暫定） | 補足文・日付 |
| --action | #39715B（暫定） | 主ボタン（白字とのコントラストは実装時に測定） |
| --focus | #2149A1（暫定） | キーボードフォーカス |

アクセント色はパステルだが、文字・アイコンには十分濃い色を使う。色だけで完了や注意を伝えない。WCAG 2.2 AAを設計目標とし、実装時に通常文字4.5:1、大文字3:1等を実測する。

### 4.2 質感・形状

- 8bitの風合いは、**直線的な濃い2px輪郭 + 2～4pxの下側影 + 局所的なピクセル装飾**で作る。
- カード角丸は8～12px。主ボタンは10～12px。極端なギザギザ形状はタップ対象の輪郭に使わない。
- 背景の全面CRT走査線・常時ノイズ・点滅は採用しない。
- 日本語本文は読みやすい丸ゴシックまたは端末標準のゴシック。英数字/時刻にのみドット風書体を補助使用。
- 初期実装では外部フォント必須にしない。追加する場合は表示性能、ライセンス、文字欠けを確認する。
- アイコンは同一グリッドサイズのSVG/ピクセルアート。無断流用のゲーム素材や効果音は使用しない。

### 4.3 サイズと余白

- モバイル最小幅320px、通常確認幅375px / 390px / 430px。
- 本文15～16px、説明13～14px、画面見出し22～28px、主結果36～52px。
- 主ボタン高さ52～56px、他のタップ領域は原則44px以上。
- 余白は8px刻みを中心に、カード内部16～20px。
- 入力・文字拡大時は横スクロールやタップ要素の重なりを発生させない。

## 5. コンポーネント仕様

| コンポーネント | 通常 | 操作中 | 完了・無効 |
| --- | --- | --- | --- |
| PixelButton | 下側3～4pxの立体影 | translateY(3px)、影を1pxへ | 完了は通常に戻す。disabledは色と操作可否を併記 |
| ChoiceCard | 輪郭2px、ラベル・アイコン | 押下で2～3px沈む | 選択時は枠と文字を保持 |
| TaskCard | 名称・分数・操作 | 新規追加時に短いスナップイン | 完了時チェックと背景色を変更 |
| TaskList | 上から順に並ぶ | 並べ替えはFLIPで位置を補間 | 順序が変わってもフォーカス保持 |
| ResultHero | 開始目安と終了目安 | 初回のみ一度出現 | 不足時間は説明と選択肢 |
| StepIndicator | いまの段階をテキストでも示す | 画面遷移に連動 | 完了済の段階へ戻れる |
| AdvancedSettings | 閉じた状態が初期値 | アコーディオン展開 | 開閉状態を維持 |
| Toast | 必要なときのみ短く表示 | 押下で消せる | 完了/保存はSR向け通知併用 |

ボタンの押し込みは擬似要素/box-shadowとtransformで実装し、レイアウトフロー自体は変えない。pointerdown/touchstartでも触感が伝わり、クリック後に機能が実行される。押しっぱなし・離したとき・操作キャンセル時の戻りを統一する。

## 7. 既存v0.1からの移行と技術構成

### 保持する機能

- Clock: deadline、buffer、タスクの分数・順番・完了状態、逆算開始時刻、不足時間の警告、時刻延長提案。
- Days: dueDate、dailyLimit、reserveDays、offDays、日割り割当、不足時間の警告。
- 生活/学習それぞれのデータ、簡易タイマー（start/pause/resume/complete）、ブラウザ保存、JSON書き出し。
- GitHub Pagesの既存公開URLとGitHub Actionsのテスト・配信。

### データ互換・移行ルール

- 現行localStorageキーは **reverse-planner:prototype:v1**。この値を無断で削除しない。
- v0.2起動時に既存値を読み取り、形式検証と必要なUIメタデータへの移行を行う。オリジナルデータのバックアップを可能にし、移行失敗時は上書きせず復旧導線を提示。
- 既存の4シートおよびdone状態・タイマーを落とさず保持。新UIが扱わないフィールドを無断で消さない。
- 保存済みデータがないユーザーの画面と、サンプル入りのv0.1から移行するユーザーの画面を分ける。デモデータの識別は必要に応じて確認付きで導入。
- v0.2の初期改修は**UIと画面状態の整理**が中心。共通計算core.mjsのアルゴリズムを変更する場合は独立したテストを追加。

### 推奨構成（現行の軽量構成を維持）

~~~text
index.html               アプリシェル
assets/app.css           現行CSS（段階的に分割可能）
assets/app.js            画面状態・保存・イベント
assets/core.mjs          既存逆算ロジック
assets/ui/               UIコンポーネント・画面別処理（必要時追加）
assets/motion.css        動きとReduced Motion設定（新規案）
assets/icons/            オリジナルまたはライセンス確認済SVG
tests/                   計算・画面遷移・保存互換性のテスト
~~~

無用なフレームワーク導入を避け、HTML/CSS/Vanilla JSを基本とする。既存のActionsワークフローは新しい公開アセットが配信対象に含まれるよう更新する必要がある（現状は個別ファイルをコピーする構成）。v0.2公開前にこれを検証。

## 8. 作業フェーズとマイルストーン

### M1｜情報設計とUI状態管理

- HOME/SETUP/PLAN/RUNの状態設計と戻る操作を実装する。
- 現行4シートを保持したまま画面表示を切り替えられる。
- サンプルと保存データの区別、既存の編集操作を担保する。
- 合格：時刻/日付の両ルートをデータ欠損なく往復できる。

### M2｜SOFT PIXELの共通部品

- 色・タイポグラフィ・立体ボタン・カード・入力・アイコンを統一する。
- モバイルから先に検証。フォーカス/disabled/エラー状態を含む。
- 合格：320～430pxとPCで読め、タップ範囲が十分にある。

### M3｜アニメーション

- 押し込み・ルートスライド・タスク追加・完了の4つを先に実装。
- Reduced Motion、フォーカス移動、素早い連続操作で破綻しないか確認。
- 合格：動きをOFFにしても機能が変わらず、操作を妨げない。

### M4｜試作レビューと公開

- 既存計算テスト、保存移行テスト、画面遷移テストを通す。
- iPhone Safari・Chrome/Edge系のスマホ・PCでクリック/タップとリロード復元を確認。
- PRレビューのうえGitHub ActionsからPagesへ反映。公開URLで目視と操作を確認。
- 合格：コード完成 / CI成功 / Web公開 / 実機操作確認の4つを別々に証跡化。

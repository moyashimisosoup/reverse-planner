# Reverse Planner｜SOFT PIXEL ロゴ設計 v1.0（画像化前ドラフト）

作成日：2026-10-17　／　状態：**デザイン設計案。画像生成・正式採用・アプリ組込み・公開は未実施。**

詳細の基礎仕様：[v0.2 UI設計](../UI_V02_PLAN.md) ／ [モーション設計](../MOTION_SPEC_V02.md) ／ [SOFT PIXELアイコン管理](../icons/README.md)

## 1. 表記と基本方針

- メインロゴ：**Reverse Planner**（RとPのみ大文字）。
- カタカナ副題：**ギャクサンプランナー**（全角カタカナ、半濁点と長音記号を省略しない）。
- タイトル2層を統一する。説明文「小さな計画で、大きな未来をつくろう。」はロゴ本体に混ぜず、周辺のコピーとして扱う。
- **文字だけで成立するロゴを先に完成**させる。ネコチャン・時計・カレンダー・山・旗は同じSOFT PIXELアイコン群から必要最小限だけ添える。
- 全文をドット体にはしない。通常本文は既存の読みやすい日本語フォントを保持する。

## 2. 書体・字形

| 対象 | 仕様 |
|---|---|
| 英字 | 太めで四角い8bit風。Pixelify Sans Boldを原形候補（Press Start 2P、自作ピクセルレタリングを比較）。英字の狭い画面での視認性を優先。 |
| 日本語 | DotGothic16を原形候補。厳密な8×8pxの低解像度化はしない。約16ドット基準の日本語字形をロゴ向けに調整。 |
| 副題の比率 | 英字の高さの約36〜46%から比較。副題を英字中央に揃える。字間は0.03〜0.08emを出発点とする。 |
| 字形チェック | 小さい「ャ」／「ヤ」、「ン」／「ソ」、「プ」の半濁点、最後の「ー」に重点。生成AIが文字を書き換えていないか1文字ずつ確認。 |
| 正本形式（制作後） | 編集可能なSVGと、文字をパス化したSVG。フォント差による表示ずれを防ぐ。 |

候補書体とライセンス：Pixelify Sans は [Google Fonts (OFL)](https://github.com/google/fonts/tree/main/ofl/pixelifysans)、日本語 DotGothic16 は [Fontworks（SIL OFL 1.1）](https://github.com/fontworks-fonts/DotGothic16)。Press Start 2P は比較用。フォント同梱・再配布時は原文のライセンスと著作権表示を確認。フォントファイルを無断公開しない。

## 4. ロゴ4形態

**A｜標準横長：優先候補。** Reverse Plannerを大きく配置し、ギャクサンプランナーを下段中央に置く。装飾は原則なし、許可する場合も山・旗の小要素のみ。基準キャンバス960×260、四辺8%以上のセーフエリア。ホーム・案内資料・OG画像向け。

**B｜フレーム付き：バナー版。** Aと同じ文字バランス。2〜4pxの段付き枠と時計またはカレンダー1点。基準960×320。バナーや導入カード向け。

**C｜ネコチャン付き：イラスト版。** 同じ文字バランスの左側にネコチャンを1匹、文字を覆わない。基本参照は RP-CATWORK-S09-I01（PC計画ネコ）、必要なら同じ作画ルールでロゴ用に再配置。星は2点程度まで。基準960×320。HOME・紹介画像向け。

**D｜コンパクト版：実用優先。** ヘッダーには短い横組み・小型マーク。正方形版は「RP」またはネコ顔のみ、カタカナ10文字は詰め込まない。ヘッダー高48〜64px、アイコン16/32/64/180/512pxで試す。表示しきれない副題はHOMEの本文に明示する。

**制作順は A（文字の形）→ D（小さくしても読めるか）→ B（枠）→ C（ネコ）。** 最初から4案の装飾だけ作らない。

## 5. ドット表現と統一ルール

- 見た目の4pxグリッドを基準としたステップ状輪郭。過度なジャギー・ぼかし・ガラス調の質感・強いグラデを避ける。
- 輪郭色は主に深い緑、背景はクリーム系。5〜7色程度で統一。
- キャラクター・歯車・フォルダ・時計・カレンダー・星は既存の196件アイコン素材（S01〜S12）と線幅・色味を揃える。
- 読むための文字と、ゲーム的な小道具としてのドット表現を分離する。
- 長い英字を320px幅に無理に1行で縮めない。2行のワードマーク版とDの簡略版を比較する。

## 6. 次フェーズの制作・検収規則

1. **画像化はまだ行わない。** Aの「文字だけ・配色3案」を生成/組版し、カタカナは実文字から別途パス化する。画像生成の誤字をそのまま製品にしない。
2. A確定後、Dを320pxのスマホヘッダーと32pxのアイコンで比較。副題が潰れる場合はサブコピーとして表示位置を変える。
3. Bではフレーム＋共通アイコン、Cでは高品質ネコ素材（HQ v5/v6）を追加する。
4. 4案の比較ボード、透過PNG（1x/2x）、編集可能SVG、単色・白抜き版、PNGアイコン180/512pxを用意する。
5. 文字の誤字なし、320/390/1280pxで横はみ出しなし、濃淡背景で視認できる、透過エッジに破損なし、iPhone Safariの実機検証を経てから本採用を判断する。
6. ヘッダー・ボタンの可読性、44px程度の操作領域、Reduced Motionへの配慮、既存アプリの計算/保存機能を維持する。

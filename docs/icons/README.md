# Reverse Planner アイコン総合台帳（初版・2026-10-17）

## 正本と収録内容

このフォルダを**アイコン管理メタデータの正本**とする。

- [ICON_REGISTRY.csv](ICON_REGISTRY.csv) : **196レコード**の個別明細。1行につき1つの管理予定アイコン。
- [SHEETS.csv](SHEETS.csv) : **12枚**の元画像シートと元ファイル名の対応。
- 対象：S01〜S10＝100件（このうち20件はネコチャン）、S11＝追加48件、S12＝柄違い48件。計196件。

### 大切な状態の区別
- **登録済み196件は管理スロットの数**であって、196点の個別PNGへの切り出し完了を意味しない。
- 12枚の元画像は会話に添付された作業環境内で**実ファイル存在を確認**したが、**GitHubには画像の実体をまだアップロードしていない**。CSVにあるファイル名だけでは原画は復元できない。
- AI生成のため、各タイルに描かれた絵柄やラベルが計画上の名称と食い違う可能性がある。**個別目視照合は未実施**。
- ネコ柄はS12の画像を見た暫定分類。確定時は必ず元画像と照合する。
- 切り出し後の採用可否、実機でのUIサイズの見え方、利用条件は別途検証する。
- 既存のアプリv0.1公開版・v0.2 Draft PRのコードには、この登録作業では手を入れない。

### IDの規則

- 主キー：`RP-<グループID>-Sxx-Iyy`（例：`RP-PATCAT-S12-I48`）
- `既存ID` は互換性のため**残す**。S01〜S10の `RP-Sxx-Iyy`、S11の `CAT-001〜048`、S12の `PAT-001〜048`。
- シート内は左から右、上から下へ採番。S01〜S10は5列×2行、S11〜S12は6列×8行。
- ファイル名は `アイコンID_日本語管理名.png` を基本とする。番号再割当は禁止し、没案は欠番ではなく「不採用」にする。

### 作業フロー

1. GitHubには**元画像のバイナリを別途保存**し、原本は上書きしない。
2. 元画像と `行`/`列` を照合し、アイコンIDと実物を一致させる。必要なら日本語管理名や柄名を修正する（主キーは固定）。
3. 個別タイルを切り出し、文字ラベルや背景を除いたアイコンをPNG/必要に応じSVGへ。透明背景の処理は品質を目視確認する。
4. `画像と名称の照合` を「済」、`切り出し状況` を「済」、`切り出しファイル` に保存先を入力。
5. UIに採用した場合のみ `採用状況` を「本採用」、`使用箇所` を記録。採用候補・本採用は混同しない。
6. 色違いや差替版を追加するときは新IDを採番し、既存ファイルへの無断上書きを避ける。

### データの実装ルール

- `ICON_REGISTRY.csv` はUTF-8・カンマ区切り、**キー重複なし**。Excelで読む場合はUTF-8として取り込む。
- ブラウザUIの必須操作は、ネコの絵だけに意味を依存させず、テキスト・ボタン・aria-labelを併用する。
- 参考デザインは[SOFT PIXEL UI計画](../UI_V02_PLAN.md) と [モーション仕様](../MOTION_SPEC_V02.md)。
- 権利関係・プライバシー・既存の開発安全規則は継続して遵守する。

## 切り出し候補の生成（2026-10-17）

- 196個の**背景付き256×256px候補PNG**と、原画の文言を残した検品用タイル196枚、シートごとの番号付き確認画像12枚を生成。
- [切り出し座標CSV](CROP_COORDINATES.csv) に元のピクセル範囲を固定。[再生成スクリプト](extract_icons.py) で原本があれば同じ座標からPNGを再生成できる。
- [アイコン明細台帳](ICON_REGISTRY.csv) の「切り出し状況」は **候補生成・要目視確認**。人による絵柄・欠け・名称の全点検、アルファ透過、アプリ正式採用は未完了。
- **画像PNGそのものはGitHub未保存**。現時点の成果物は会話の「reverse_planner_icons_196_extraction_review_pack_v1.zip」に原画12枚・切り出し画像196枚・検品タイル196枚・確認一覧12枚・Excel台帳と再生成スクリプトを同梱して渡す。元画像のバックアップ先を確定してから長期保存すること。
- GitHubに保存したものは、現時点で **管理台帳・座標台帳・再生成用コード** である。
